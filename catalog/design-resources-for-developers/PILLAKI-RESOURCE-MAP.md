# Mapa de recursos para Pillaki

Esta guía traduce el índice `bradtraversy/design-resources-for-developers` a usos concretos para futuras webs y sistemas de clientes.

## Prioridad alta

### UI Graphics / UI Components / Design Systems
Para inspiración de interfaces, componentes, patrones, estados, dashboards, formularios y sistemas visuales.

### Fonts
Para selección, pairing, self-hosting y validación de tipografías. Antes de usar una fuente en un cliente, verificar su licencia comercial.

### Colors
Para paletas, contraste, escalas, accesibilidad y sistemas de color.

### Icons / Logos / Favicons
Para iconografía y herramientas de generación. Verificar siempre licencias, marcas y condiciones de atribución.

### Image Compression
Útil para rendimiento y Core Web Vitals antes de subir imágenes a producción.

### CSS / JavaScript Animations
Para microinteracciones, motion, scroll effects y efectos visuales. Preferir soluciones ligeras y compatibles con `prefers-reduced-motion`.

### JavaScript Chart Libraries
Para dashboards, reportes, métricas, paneles de clientes y visualización de datos.

### React UI Libraries
Útiles para investigar alternativas y patrones; para proyectos React/Next.js, `shadcn/ui` sigue siendo la base preferente de nuestra biblioteca salvo que otro recurso resuelva mejor el caso.

## Prioridad media

### Stock Photos / Videos / Music / Sound Effects
Solo cuando el proyecto lo requiera. Cada asset debe revisarse por separado antes de uso comercial.

### Vectors / Clip Art / Mockups
Útiles para presentaciones, demos y piezas comerciales. Verificar licencia del archivo concreto.

### HTML & CSS Templates
Usarlos principalmente como referencia o punto de aprendizaje. Evitar copiar templates completos a producción sin auditoría de licencia, calidad, dependencias, accesibilidad y rendimiento.

### Online Design Tools / Inspiration
Buenos para exploración visual, benchmarking y generación de ideas. No confundir inspiración con permiso para copiar.

## Flujo Pillaki recomendado

1. Definir la necesidad concreta del proyecto.
2. Consultar este radar para descubrir candidatos.
3. Abrir la fuente original del candidato.
4. Revisar mantenimiento, seguridad, licencia, coste y compatibilidad.
5. Comparar con herramientas ya existentes en `sf-design-skills-library`.
6. Elegir solo si aporta una ventaja real.
7. Probar de forma aislada antes de producción.
8. Documentar atribución y versión cuando corresponda.

## Regla de oro

Este repositorio sirve para **encontrar** recursos. No convierte automáticamente los recursos enlazados en libres, seguros, actuales ni apropiados para un cliente.
